# Читаемый BSL diff и перемещения методов

Пользователь согласовал реализацию: полный diff сохраняет порядок исходников и
переходы между местами перемещения; отдельная вкладка сравнивает тела выбранного
перемещённого метода рядом. Исправляются также захват неизменных начал конструкций
и чтение новых функций на светлой теме.

## Подходы

Выбран: доработать существующие EDT parser + JGit + SWT. Сопоставление методов
предшествует сравнению содержимого. Один результат задаёт подсветку и перемещения.
Переиспользовать viewer для отдельного сравнения метода без действий записи.

Рассмотрены: выравнивать перенесённые методы прямо в полном файле (ломает порядок
исходников и усложняет прокрутку); заменить движок (лишняя интеграция при известных
дефектах текущей логики). Эти варианты не выбраны.

## Поведение

- Уникальные методы сопоставляются по виду и имени без учёта регистра. Область и
  условная компиляция — контекст, а не причина отключить весь модуль.
- Различать порядок, контекст и текст. Изменение номеров строк само по себе не
  означает перемещение. Перемещение между областями имеет парные отметки, даже
  если порядок других методов не изменился. Перемещённый метод с правкой получает
  также точную локальную подсветку.
- Условные директивы внутри полного, корректно разобранного метода не отключают
  его сопоставление. Для неоднозначных дубликатов и неполного разбора применять
  честный текстовый fallback; не объявлять непроверенные участки одинаковыми.
- Точные границы методов берутся из разбора EDT. Вставка функции не должна
  подсвечивать начало соседней. Внутри метода сначала привязать изменённые строки,
  затем уточнить токены в этих участках; одинаковые начала условий/строк не должны
  получать подсветку из соседних конструкций.
- Обычные цвета синтаксиса и начертание сохраняются. Новые/удалённые блоки получают
  слабый фон и знаки на полях. Локальные изменения — более заметный фон без
  принудительной жирности и подчёркивания. Светлая и тёмная темы читаемы.
- Пользователь выбрал визуальный вариант A: одна метка перехода у объявления,
  тонкая синяя полоса вдоль метода, без стрелок на каждой строке, без синей
  заливки тела и без выделения номеров для перемещения.
- Парные переходы и общий scrollbar сохраняются. Действие «Сравнить метод»
  открывает отдельную read-only вкладку с именем метода и исходными координатами;
  доступно для выбранного перемещения. Там нет Apply и нет самостоятельной записи.
- Для неоднозначных одноимённых методов не применять эвристическое переименование.

## Ограничения и проверка

Без новых runtime-зависимостей и внешнего процесса. Сохранить opt-in jgit,
ограничения 524288 UTF-16 / 20000 строк, отмену и бюджет вычисления, точные байты
подготовленной записи и все существующие approval/commit guards. MCP textDiff
из 02874010 не менять. Рабочая ветка локальная, после проверки локальное слияние
в master; без push и PR. Чужие изменения не включать.

Регрессии: перенос с #Если, перенос между областями, перенос с правкой,
добавление функции перед неизменной, повторяющиеся условия/вызовы, сдвиг строк,
неоднозначные имена, синтаксическая ошибка, BOM/CRLF/кириллица. Проверять реальные
токены EDT и SWT стили. Автоматические GUI-прогоны только в Xvfb. Пользователь выбрал установку в существующий EDT для workspace
`/home/ownicc/.local/share/1C/1cedtstart/projects/Kasl`. Новые workspace/скрипты
запуска не создавать. Видимый пример открывать в этом EDT без применения правок.
