# Правила работы с проектом

## Git

- Разрабатывать и проверять изменения в локальных рабочих ветках.
- После завершения и проверки объединять изменения локально в `master`.
- Отправлять в `origin` только ветку `master` (`git push origin master`).
- Рабочие ветки не публиковать. Pull requests не создавать.
- Выпускать релизы из коммитов, уже включённых в `master`.
- Этот порядок не означает автоматическое удаление ранее опубликованных веток.

## Навигация по коду

- Перед исследованием задачи сначала вызывать `codedb_context`; codedb использовать
  для навигации, а изменения выполнять штатными инструментами редактирования.
- Для структурного исследования использовать установленный skill `codebase-memory`.
