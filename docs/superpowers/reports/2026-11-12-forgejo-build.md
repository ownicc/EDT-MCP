# Сборка плагина в GitHub Actions и Forgejo

## Реализация

GitHub и зеркало Forgejo используют отдельные workflows и общую локальную
action `.github/actions/build-plugin`. В общей action находятся проверки
skills, три Python-набора, Maven/Tycho с Java-тестами, JaCoCo и версия артефакта.
JDK 25, Maven 3.9.16, EDT guard и Maven retry сохранены. GitHub сохраняет
SonarCloud, публикацию результатов, остальные workflows, релизы и Pages.

Forgejo checkout использует собственный сервер, приватный репозиторий,
CI-токен и SHA события. Артефакты сохраняются через совместимый
`upload-artifact@v3-node20`; отсутствие p2-результата завершает upload ошибкой.

- Python: 325 тестов (5 update-site, 5 docs, 315 E2E runner), без ошибок.
- Первая полная общая сборка: 13 848 Java-тестов, 25 пропусков, без ошибок.
- После включения параллельно поступившего BSL navigation в рабочую ветку:
  13 853 Java-теста, 26 пропусков, без ошибок; JaCoCo XML создан.
- Последнее уточнение UI из `master` проверено отдельным прогоном двух
  затронутых классов под Xvfb: 7 тестов, без пропусков и ошибок. Полный набор
  повторно ради этой визуальной правки не запускался.
- Собранный p2 проверен существующим `validate-update-site.py`: согласованные
  metadata и bundle/feature JAR; последний локальный qualifier —
  `1.0.0.202611121843`.
- GitHub workflow прошёл actionlint 1.7.12. Forgejo Runner 13.1.0 подтвердил
  workflow и все четыре локальные action своей схемой. Shell-блоки проверены.
- Независимое ревью конфигурации: замечаний Critical/Important/Minor нет.

## Runner и развёртывание

Пользователь указал `koara_main` как машину размещения. На ней создан отдельный
Compose stack `/home/ownicc/docker/stacks/forgejo-runner` с runner 13.1.0
`koara-edt-mcp`, зарегистрированным только для `ownicc/EDT-MCP`, label `edt-build`.
Работает одно задание одновременно, с лимитом 4 CPU / 8 ГБ. Задания запускаются
в `node:24-bookworm` через отдельный Docker-in-Docker daemon. Хостовый Docker
socket в runner и задания не передаётся; порт Docker API наружу не публикуется.
Кеш хранится в stack data и доступен заданиям через внутренний gateway DinD.

Параметр `BUILD_RUNNER`, использованный до выяснения инфраструктуры, удалён:
workflow теперь явно выбирает проверенный `edt-build`. Смена этого label
потребует соответствующего изменения workflow.

Файл `.runner` имеет права 600, его каталог — 700. Ошибочно выведенный при
диагностике токен регистрации отозван; замена проверена. После регистрации новый
enrollment token также деактивирован. Пользовательский PAT не сохранялся в коде
или конфигурации runner.

## Зависимость SWT в образе Forgejo

Автоматический run 2 подтвердил запуск после синхронизации SHA `92c836f4`.
При выполнении тестов обнаружена отсутствующая в базовом Node-образе
`libgtk-3.so.0`: SWT `Display` не инициализировался, что приводило в том числе
к ошибкам загрузки Xtext-провайдеров в тестах СКД. Отдельный свежий JVM-процесс
в том же контейнере воспроизвёл `UnsatisfiedLinkError` при загрузке `Display`.
После установки только `libgtk-3-0` тот же вызов завершился успешно.
Итог старого run 2: одна failure и 160 errors, 43 пропуска из 13 855 тестов.
Пакет добавлен в подготовку Forgejo job; тесты не пропускаются и не изменяются.
Чистый run 3 с этой зависимостью прошёл весь набор без failures/errors.

## Границы результата

Поддержка обычной сборки подтверждена обоими CI на указанном приёмочном SHA.
Более поздние параллельные изменения BSL UI не входят в этот прогон; ссылки
выше фиксируют проверенный исходный код, а не обещают результат будущих запусков.
Релизы, Pages, SonarCloud и отдельные E2E/conformance workflows остаются на GitHub.
Исходные незакоммиченные файлы другого задания сохранены. Worktrunk с рабочей
веткой оставлен локально.

## Пропуск сборки при изменениях документации

По запросу пользователя оба Build workflow получили одинаковый список `paths`
для автоматического запуска; GitHub использует его также для `pull_request`.
README, changelog, обычные страницы документации, планы, отчёты и макеты
не запускают Maven/Tycho. Исходники плагина, его ресурсы и зависимости,
общие actions/scripts, оба build workflow, Python-проверки в `docs/`, E2E inputs,
пакет `agent/` и `.gitattributes` продолжают запускать сборку. Ручной
`workflow_dispatch` сохранён без фильтра.

Проверено 18 сценариев путей, равенство фильтров двух платформ и GitHub PR,
неизменность содержимого jobs; actionlint и схема Forgejo Runner 13.1.0 прошли.
Полная Maven-сборка локально для изменения условий запуска не повторялась.
