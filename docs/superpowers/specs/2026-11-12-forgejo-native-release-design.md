# Независимая релизная сборка Forgejo

Пользователь согласовал: Forgejo собирает релизный тег с тестами общей action
и публикует полученный p2; GitHub продолжает свою независимую цепочку.
GitHub Release API, ожидание архива и его скачивание из публикации убираются.
URL сайта и существующий repository-scoped token сохраняются.

Workflow проверяет стабильный `vX.Y.Z`, checkout-ит исходники этого тега с полной
историей и проверяет его включение в master. Инструменты CI из master помещаются
в отдельный `.release-tools`: старые теги ещё не содержат общей action.
JDK25, Maven3.9.16, GTK3, EDT guard и кеш остаются теми же, что в обычной сборке.
После Tycho set-version выполняется общая action со всеми Python/Java-тестами.
Публикация потребляет локальный p2-каталог и подтверждает HEAD тега. Новый
`release.json` содержит SHA исходников и ссылку на тег в Forgejo.

Ручной запуск требует явный тег; выбор latest через GitHub исчезает. Публикация
из master без тега запрещена. Сохраняются атомарный push, проверка p2, старые JAR,
запрет downgrade и идемпотентность. Уже опубликованная версия не перезаписывается;
для нового marker несовпадение SHA того же номера версии считается ошибкой.

Приёмка: регрессии publisher, схема workflow, полный реальный запуск на v1.0.6,
проверенный артефакт собственного build и успешный безопасный no-op публикации
существующей 1.0.6. Новый релиз ради проверки не создаётся. Обычные CI-фильтры,
GitHub release/Pages и встроенное уведомление плагина не меняются.
