# Стабильный p2 update site в Forgejo

Пользователь поручил настроить предложенную публикацию сайта из успешного
стабильного релиза. GitHub Releases остаётся источником проверенного релизного
архива; обычные сборки master и документация не публикуют обновления.

Выбранный исполнителем способ: отдельный публичный репозиторий
`ownicc/EDT-MCP-update-site` с готовыми p2-файлами и постоянным URL
`https://forgejo.ownicc.ru/ownicc/EDT-MCP-update-site/raw/branch/master/`.
Новый веб-сервер не нужен. Вариант со статическим сервером потребовал бы
доступа CI к хосту; package registry не предоставляет стандартную структуру
каталогов p2 без дополнительного преобразования.

Отдельный лёгкий Forgejo workflow запускается по стабильному тегу `vX.Y.Z`
и вручную. Он ждёт появления успешного стабильного GitHub Release, загружает
его p2 ZIP, проверяет существующим валидатором и публикует одним git-коммитом.
Тег должен указывать на коммит зеркального master. Maven не запускается.
Ожидание ограничено 30 минутами, поскольку зеркало может получить тег раньше
завершения релизной сборки. Ручной запуск без тега выбирает latest stable release.

Новый токен ограничен `write:repository` и только репозиторием p2; хранится
в Forgejo Actions secret, не в исходном коде и не в git URL.
Загрузка/валидация выполняются до изменения опубликованной ветки.
Старые JAR сохраняются для клиентов, уже прочитавших предыдущие metadata.
Публикация более старой версии запрещена; повтор той же версии безопасен.

Приёмка: существующий стабильный релиз v1.0.6 доступен анонимно по новому URL,
metadata и оба JAR проходят валидатор; Eclipse p2 director читает репозиторий.
GitHub Pages, фильтры обычных сборок и встроенное уведомление UpdateChecker
с адресом GitHub не меняются. В EDT пользователь добавляет новый update site
вместо прежнего адреса; это дополнительный канал распространения тех же релизов.
