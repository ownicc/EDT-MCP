# read_method_source

Inspect the source of one or more BSL procedures or functions. Parameters and examples: get_tool_guide('read_method_source').

## Parameters
| Parameter | Required | Type | Description |
| --- | --- | --- | --- |
| projectName | yes | string | EDT project name |
| modulePath | yes | string | Path from src/, e.g. 'CommonModules/MyModule/Module.bsl' |
| methodName | — | string | Procedure/function name (case-insensitive) |
| methodNames | — | array | Several procedure/function names read in one call (up to 50); use instead of methodName. One of the two is required. |

## Guide
Reads one or more procedures or functions out of a BSL module by name - so you get the 40 lines you care about instead of a 60,000-line file. The body comes back with its contiguous doc-comments and ampersand directives, plus a metadata header you can feed straight back into an edit.

## When to use
- You know the method name and just want to read its implementation.
- You need several methods from the same module: pass `methodNames` for one saved-file read and one `contentHash`.
- You are about to edit a method and need its current body plus the `methodHash` for a safe `replaceMethod` write.
- Cheaper, more focused alternative to reading the whole module.

## Parameter details
- `projectName` (required) - the EDT project.
- `modulePath` (required) - the module from `src/`, e.g. `CommonModules/MyModule/Module.bsl`.
- `methodName` - one procedure/function name, **case-insensitive**.
- `methodNames` - an array of up to 50 names read in one call (more is refused - split the list or use `read_module_source`). Case-insensitive duplicates are read once.
- One of `methodName` / `methodNames` is required. Both may be given: `methodName` is read first, then the list, in request order.

## What you get
`methodName` alone returns Markdown with a YAML front-matter block (projectName, module, `contentHash`, `methodHash` when the target is safely addressable, method, type, export flag, startLine/endLine, totalLines, and region) followed by the source in a ```bsl``` fence. Both hashes and the displayed source come from the same saved-file read. If the method participates in extension interception, that is noted below the code.

`methodNames` returns one module front matter (`contentHash`, `totalLines`, `methodsFound`, and `methodsNotFound` when any), followed by a `### <Name>` section per found method in request order. Each section has its type, export flag, lines, optional region and `methodHash`, then its code fence. All hashes and source sections describe the same saved-file snapshot.

## Notes & gotchas
- **Method not found?** When none of the requested names exists it returns the list of available method names in that module - copy the exact one and retry. With `methodNames`, names that exist are still returned and the rest are listed in `methodsNotFound`. (Name matching ignores ru/en keyword dialect.)
- The `contentHash` is a whole-MODULE revision token, not a per-method one. Pass it as `expectedHash` to `write_module_source` for an optimistic-lock safe edit; the same token is produced by `read_module_source`, so the two agree.
- For `write_module_source` with `mode="replaceMethod"`, pass `methodHash` as `expectedMethodHash` to guard just this method. An unrelated method edit does not invalidate this token. The token covers the exact replacement span: contiguous doc-comments and ampersand directives, declaration, body, and terminator. Changes anywhere in that span invalidate it.
- Method hashing joins the span's saved lines with LF and adds no trailing newline. UTF-8 BOM and CRLF/LF differences do not change the token; surrounding blank separators and regions are outside its scope. The code fence adds a display newline before its closing fence.
- Missing, ambiguous, incomplete, or scanner-unaddressable targets receive no `methodHash`. A legacy read can still display a fragment when it cannot safely identify a replacement target. If reading the saved file fails, or its declaration cannot be located by the text scanner, a known native method can still be displayed from the model; neither revision token is returned for that model-only source.
- To list the methods in a module first, use `get_module_structure`; to read the entire module, use `read_module_source`.
