# Сборка плагина в GitHub Actions и Forgejo

## Реализация

GitHub и зеркало Forgejo используют отдельные workflows и общую локальную
action `.github/actions/build-plugin`. В общей action находятся проверки
skills, три Python-набора, Maven/Tycho с Java-тестами, JaCoCo и версия артефакта.
JDK 25, Maven 3.9.16, EDT guard и Maven retry сохранены. GitHub сохраняет
SonarCloud, публикацию результатов, остальные workflows, релизы и Pages.

Forgejo checkout использует собственный сервер, приватный репозиторий,
CI-токен и SHA события. Артефакты сохраняются через совместимый
`upload-artifact@v3-node20`; отсутствие p2-результата завершает upload ошибкой.

## Runner и развёртывание

Пользователь указал `koara_main` как машину размещения. На ней создан отдельный
Compose stack `/home/ownicc/docker/stacks/forgejo-runner` с runner 13.1.0
`koara-edt-mcp`, зарегистрированным только для `ownicc/EDT-MCP`, label `edt-build`.
Работает одно задание одновременно, с лимитом 4 CPU / 8 ГБ. Задания запускаются
в `node:24-bookworm` через отдельный Docker-in-Docker daemon. Хостовый Docker
socket в runner и задания не передаётся; порт Docker API наружу не публикуется.
Кеш хранится в stack data и доступен заданиям через внутренний gateway DinD.

Параметр `BUILD_RUNNER`, использованный до выяснения инфраструктуры, удалён:
workflow теперь явно выбирает проверенный `edt-build`. Смена этого label
потребует соответствующего изменения workflow.

Файл `.runner` имеет права 600, его каталог — 700. Ошибочно выведенный при
диагностике токен регистрации отозван; замена проверена. После регистрации новый
enrollment token также деактивирован. Пользовательский PAT не сохранялся в коде
или конфигурации runner.

## Живая проверка

Код включён в `master` и отправлен только в `origin/master`, рабочая ветка
не публиковалась, PR не создавался. Исходный rollout SHA:
`fd0e9ac990d282d80c5ac13c767d7d09e9a8ea70`.

Зеркало получило этот SHA и `.forgejo/workflows/build.yml`; после этого Actions
включены в репозитории. Ручной dispatch принят с HTTP 204 и создал выполняющийся
[Forgejo run 1](https://forgejo.ownicc.ru/ownicc/EDT-MCP/actions/runs/1).
[GitHub Build](https://github.com/ownicc/EDT-MCP/actions/runs/43282978928)
того же SHA также выполняется. Более ранний GitHub run от 11 ноября оставался
в очереди, но новый run начал выполнение.

На момент этой записи оба запуска ещё не завершены. Успешная загрузка/скачивание
артефактов и автоматический запуск от следующего обновления зеркала требуют
подтверждения; поддержка обоих CI пока не объявляется проверенной.

## Зависимость SWT в образе Forgejo

Автоматический run 2 подтвердил запуск после синхронизации SHA `92c836f4`.
При выполнении тестов обнаружена отсутствующая в базовом Node-образе
`libgtk-3.so.0`: SWT `Display` не инициализировался, что приводило в том числе
к ошибкам загрузки Xtext-провайдеров в тестах СКД. Отдельный свежий JVM-процесс
в том же контейнере воспроизвёл `UnsatisfiedLinkError` при загрузке `Display`.
После установки только `libgtk-3-0` тот же вызов завершился успешно.
Пакет добавлен в подготовку Forgejo job; тесты не пропускаются и не изменяются.
Для приёмки требуется новый запуск из неизменённого вручную контейнера.
