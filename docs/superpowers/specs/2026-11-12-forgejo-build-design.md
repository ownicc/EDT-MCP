# Сборка плагина в GitHub Actions и зеркале Forgejo

Дата: 2026-11-12. Статус: код реализован и интегрирован; выполняется проверка в обоих CI.
Рабочая ветка: `design/forgejo-build`, создана через Worktrunk от `master`.

## Цель и границы

Пользователь выбрал отдельные workflows с общей логикой сборки. GitHub Actions
продолжает собирать плагин; зеркало Forgejo независимо собирает тот же исходный
коммит и предоставляет установочный p2-артефакт. GitHub остаётся источником
изменений, существующее зеркало сохраняется.

В эту задачу входят обычная сборка плагина с тестами и сохранение её результата.
Перенос GitHub Releases, GitHub Pages, SonarCloud, отдельных E2E/conformance
workflows и сборки proxy в Forgejo в эту задачу не входит. Существующие проверки
и публикации на GitHub должны продолжить работать. Требования к побайтовому
совпадению артефактов нет: квалификаторы и время сборки могут различаться.

## Рассмотренные подходы

1. Единый workflow с условиями для GitHub и Forgejo: меньше файлов, но условия
   смешивают настройки двух платформ и несовместимые actions публикации.
2. Отдельные workflows с общей локальной логикой: немного повторяется описание
   окружения и кеша, зато команды проверок и сборки определяются один раз.
   Пользователь выбрал этот вариант.

## Устройство

- `.github/workflows/build.yml` остаётся workflow GitHub.
- `.forgejo/workflows/build.yml` становится отдельным workflow Forgejo.
- Новая локальная composite action `.github/actions/build-plugin/action.yml`
  содержит общие шаги: проверку business-project skills, Python-тесты валидатора
  update site, генератора документации и E2E runner, Maven `clean verify` через
  существующий `mvn-retry.sh`, отчёт JaCoCo и извлечение версии из manifest.
  Action выполняется после подготовки JDK/Maven и кеша, не загружает внешние
  actions и возвращает версию для имени артефакта. Это предложение исполнителя
  по организации выбранной пользователем общей логики.
- Оба workflow вызывают эту action. Сохраняются JDK 25, Maven 3.9.16, Tycho 5.0.4
  и текущие Maven-параметры; тесты при обычной сборке не пропускаются.
- Существующие локальные actions `setup-maven` и `edt-channel-guard`, а также
  скрипты `edt-pin.sh` и `mvn-retry.sh` переиспользуются без переноса каталогов.
  Проверка канала EDT выполняется до Maven; кеш p2 учитывает target и сборку EDT.
- Checkout, выбор runner, кеширование и публикация артефактов задаются отдельно
  для каждой платформы. GitHub сохраняет SonarCloud и публикацию результатов
  тестов в GitHub Checks. Forgejo сохраняет p2-каталог как скачиваемый артефакт
  и отчёты тестов для диагностики, без вызовов GitHub API.
- В Forgejo внешние actions указываются полными URL. Для артефактов выбирается
  поддерживаемая Forgejo 15 версия, проверенная с установленным runner; текущие
  GitHub `upload-artifact@v7`/`download-artifact@v8` автоматически не копируются.
  Кеш должен быть доступен из контейнера job; его работоспособность проверяется
  отдельно от корректности самой сборки.

## Запуск и доступы

GitHub сохраняет текущие события `push` в `master`, `pull_request` в `master`
и ручной запуск. Forgejo запускает сборку после обновления зеркального `master`
и допускает ручной запуск. Рабочие ветки не публикуются, прямой push в зеркало
не требуется. Пользовательский PAT используется локально для настройки и
диагностики; checkout workflow использует выдаваемый CI токен репозитория.

На момент исследования Forgejo сообщает `15.0.11`, репозиторий
`ownicc/EDT-MCP` имеет `mirror=true`, `has_actions=false`; его `master` совпадает
с исходным локальным `bf39784c`. Наличие и параметры runner не подтверждены:
GET runner репозитория вернул 404, runner пользователя — 403.
Эти ответы не доказывают отсутствие runner.

До реального запуска надо проверить включение Actions на сервере и в репозитории,
доступный runner, его версию, label и образ Linux x86_64 с инструментами для
выбранных actions, Bash и Python. Runner нужен сетевой доступ к Forgejo, выбранным
actions, Maven Central, репозиториям EDT и Eclipse. Точное значение `runs-on`
задаётся после проверки runner, а не выводится из GitHub `ubuntu-24.04`.

Исходный код Forgejo 15.0.11 связывает обновление зеркала с уведомлением `push`.
Это основание для проектирования запуска, но фактический автоматический запуск
на пользовательском сервере должен быть подтверждён экспериментом. При включении
Actions сначала должен быть доступен адаптированный `.forgejo/workflows`, иначе
Forgejo может использовать существующие `.github/workflows`.

## Проверка результата

До интеграции проверяются синтаксис YAML/composite actions и переход существующего
GitHub workflow на общие шаги, выполняются перечисленные Python-проверки и полная
Maven-сборка с Java-тестами. Артефакт должен содержать согласованные p2-метаданные,
bundle и feature JAR; отсутствие выходного каталога считается ошибкой публикации.

Окончательная приёмка требует успешных запусков GitHub и Forgejo для одного SHA
`master`, скачивания установочного артефакта с каждой платформы и проверки его
содержимого. Для Forgejo дополнительно проверяются ручной запуск и автоматический
запуск после обновления зеркала. Пока этих запусков нет, поддержка двух CI не
считается проверенной. После локальных проверок изменения интегрируются в `master`
по правилам проекта; публикуется только `origin/master`, pull request не создаётся.
